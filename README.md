# Orthogonal Dictionary Learning for Quantitative MRI

This repository provides a **small-scale MATLAB implementation** of the orthogonal dictionary-learning approach to quantitative MRI (qMRI) presented by [Dong, Hintermüller, and Sirotenko (2025)](https://iopscience.iop.org/article/10.1088/1361-6420/adef74). The emphasis is on small-scale numerical experiments, with adaptations to parameter scaling, initialization, and solver settings.

The examples recover longitudinal relaxation time $T_1$, transverse relaxation time $T_2$, and proton density $\rho$ from simulated, undersampled Fourier measurements generated with a Bloch model.

The main demonstration compares BLIP, projected Levenberg-Marquardt (LM), one-step dictionary learning, and nested dictionary learning using the same measurements and coarse-BLIP initialization.

## Tested environment

The code has been tested on a **Dell XPS 17 laptop running Windows with MATLAB R2021b**.
The notebook is an XPS 17 9710 with an Intel Core i7-11800H processor (8 cores, 16 threads), 64 GB RAM, and an NVIDIA GeForce RTX 3060 Laptop GPU, running Windows 11 Home.

- MATLAB R2021b.
- Optimization Toolbox for the dictionary-regularized reconstruction routines, which use `quadprog`.

The current implementation is best used at **128 x 128 pixels**, which is the recommended starting resolution for the supplied experiments.

## Quick start

1. Download or clone this repository and open its root folder in MATLAB.
2. Open [`demo_compare_all_reconstructions.m`](demo_compare_all_reconstructions.m).
3. The script loads the saved **128 x 128 baseline** by default (`pixel_stride = 2` on a 256 x 256 source). Select only `reconstruction_parameters_256()` in its parameter section for full resolution. Review the input and plotting settings in the demo and the algorithm settings in the selected preset file.
4. Run the script from the MATLAB Command Window:

```matlab
demo_compare_all_reconstructions
```

The default input is a **synthetic phantom**, generated by `create_artificial_ground_truth(10,256)` and written to `data/artificial_maps.mat` on every run. To use the supplied brain maps or your own MAT file, comment out all three active phantom-generation lines in the demo's input section, then enable or set `input_file`. The phantom's complexity controls its regions and texture; the preset's `seed` controls measurement noise.

The script adds its helper folders to the MATLAB path automatically. It displays reconstructions and diagnostics, and saves `results.mat`, four PDF reports (`maps.pdf`, `errors.pdf`, `convergence.pdf`, and `profiles_and_summary.pdf`), and eight compact PDFs in a new `data/comparison_all_<timestamp>/` folder. Generated results are excluded from Git.

The eight additional PDFs have small margins and linked zoom insets:

- `T1_map_comparison.pdf` and `T1_error_comparison.pdf`
- `T2_map_comparison.pdf` and `T2_error_comparison.pdf`
- `Density_map_comparison.pdf` and `Density_error_comparison.pdf`
- `initialization_maps.pdf` and `initialization_errors.pdf`

Each of the six comparison files contains one row in this order: **ground truth, BLIP, Levenberg-Marquardt, one-step dictionary learning, nested dictionary learning**. Error panels show absolute differences from ground truth (milliseconds for T1/T2, original density units); the ground-truth error panel is zero. Every row shares one colorbar. Each initialization PDF contains **T1, T2, and density**, with a separate colorbar for each parameter. Color limits and the zoom region match the comparison PDFs.

Adjust `design.RowPanelSize`, `design.RowPanelGap`, and `design.RowShowTitles` in the demo to control the compact layout; set `RowShowTitles=false` to omit comparison method headings. Both initialization PDFs always omit headings and parameter labels, keeping the colorbars and numeric ticks. `MapLimits`, `ErrorLimits`, `MapColors`, `ErrorColors`, `ZeroBackground`, and `ZoomBox` apply to both the existing comparison grid and the compact PDFs.

`design.ZoomBox = [first_row last_row first_column last_column]` uses inclusive indices on the **reconstructed, downsampled grid** and must span at least two rows and columns. Leave it empty for automatic selection. `design.ProfileRow=[]` selects the middle reconstructed row. Map and error color limits use physical units; values above the limits saturate in the plots without changing the saved maps or error metrics.

The eight compact PDFs are exported without opening figure windows by default (`design.ShowRowFigures=false`); each hidden figure is closed after export. Set `design.ShowRowFigures=true` to inspect those figures on screen as well. The master switch `design.ShowFigures=false` hides all report and compact figures while still saving the PDFs.

To generate only the eight compact PDFs from an existing experiment, without rerunning the solvers:

```matlab

[pdf_paths, zoom_box] = export_reconstruction_rows(s.truth,s.reconstructions, ...
    s.u0,s.mask,s.method_names,s.design,run_folder);
```

This replaces any compact PDFs with the same filenames; the saved `results.mat` and four existing reports are unchanged. Missing compact-layout settings in older runs use the defaults.

## Saved parameter sets

Two editable MATLAB functions store the acquisition settings, physical bounds/scales, BLIP grids and initialization options, and the BLIP, LM, one-step DL and nested DL solver options:

- [`reconstruction_parameters_128.m`](reconstruction_parameters_128.m): the current four-method comparison settings, saved as the 128 x 128 baseline.
- [`reconstruction_parameters_256.m`](reconstruction_parameters_256.m): the standard 256 x 256 configuration from the supplied four-method comparison, with `pixel_stride = 1`, `r = 32`, noise SD `1`, and 80 outer steps for both DL methods. It is independent of the 128 x 128 preset.

Load either set as a MATLAB structure:

```matlab
parameters = reconstruction_parameters_128();
% parameters = reconstruction_parameters_256();
```

In `demo_compare_all_reconstructions.m`, select the desired function in **Load saved experiment and algorithm parameters**. These functions return a plain MATLAB structure without running a reconstruction or changing files. Keeping configuration in small `.m` functions makes the values readable, records edits in Git, and allows derived quantities such as dictionary grids and initial damping to be computed from the same settings.

### Changing parameters

**To save a new default, edit the values inside the selected preset function.** For example, to tune the 256 x 256 configuration:

1. Open `reconstruction_parameters_256.m` in the MATLAB Editor (`edit reconstruction_parameters_256`).
2. Change acquisition variables such as `r` or `noise_std`, or values in the relevant options structure. For example, change `'MaxIterations',15` to `'MaxIterations',20` inside `lm_options=struct(...)` to increase the LM budget. This is an editing example, not a recommendation to use 20 iterations.
3. Save the file. The final `parameters=struct();` block only collects the settings for return; normally leave that block unchanged.
4. Select `parameters=reconstruction_parameters_256();` in the demo and run it. The 128 x 128 preset remains unchanged.

Within each preset, `nested_options=one_options` copies the one-step DL settings before adding the nested-specific controls. Editing the original `one_options` definition therefore changes both methods' shared settings. To change only nested DL, edit or add a `nested_options.<field>=...` assignment after that copy and before the final return block. To change only one-step DL, place its override after the copy as well.

**For a temporary experiment, override the returned structure in the demo.** Place overrides immediately after the preset-loading line and before the demo copies its fields into working variables:

```matlab
parameters = reconstruction_parameters_256();
parameters.lm_options.MaxIterations = 20;       % Example one-run override.
parameters.nested_options.InnerMaxIterations = 1500;
```

These assignments leave the preset file unchanged and apply on every run until removed from the demo. After loading, `parameters.one_options` and `parameters.nested_options` are independent copies; change both explicitly if an override should affect both. Change dependent settings such as bounds, grid spacing or `r` inside the preset function so the grids, BLIP step sizes and LM damping are rebuilt together. Assigning `parameters.r` after loading does not recompute those derived values.

### Current choices and their roles

The 128 x 128 preset records the current baseline, while the 256 x 256 preset records the supplied standard configuration. Their weights, iteration budgets and tolerances are practical choices for these setups; they are not claimed to be optimal for other inputs, noise levels or resolutions. Values below apply to both presets unless a resolution is specified.

| Setting in the preset | Current value | Purpose and effect of changing it |
| --- | --- | --- |
| `L`, `r`, `TR_ms`, `noise_std`, `seed` | 128: `100`, `16`, `12`, `1.5`, `1`; 256: `100`, `32`, `12`, `1`, `1` | Define the common simulated acquisition. Noise SD applies separately to real and imaginary parts. The seed fixes the random draw for a given setup. |
| `lower_bounds`, `upper_bounds`, `scales`, `reference_times` | `[100 10 0]`, `[5500 600 110]`, `[5000 500 100]`, `[1000 100]` | Define the admissible physical maps and shifted, scaled optimization coordinates. Time values are in ms. Changing scales also changes the DL prior in physical units, so review its weights. |
| `coarse_spacing`, `initial_options`, `initial_use_body_mask` | `[200 50]` ms; 29 x 14 grid; at most 20 trials; mask enabled | Build a common coarse-BLIP start at lower dictionary cost. Rejected trials count toward the budget. The mask resets initial background pixels to `[reference_times 0]`; later solvers keep those pixels free. |
| `fine_spacing`, `blip_options.MaxIterations` | `[100 10]` ms; 55 x 60 grid; at most 30 accepted updates | Refine the BLIP time grid and allow further reconstruction updates. Smaller spacing increases dictionary size and matching cost. The coarse grid is included in the fine dictionary. |
| `lm_options` damping and budget | `InitialDamping=r^2` (256: `1024`), `DampingDecay=0.15`, `MinDamping=1e-8`, `MaxIterations=15` | Control stabilization and the number of projected LM updates. A smaller decay reduces damping faster; more updates can improve the data fit but also fit more noise. |
| DL `Alpha`, `Lambda`, `Beta`, `PatchSize` | Both: `Alpha=0.7`, `[8 8]` patches; 128: `Lambda=[10.75 37.5 37.5]*1.5`, `Beta=[.009 .009 .009]*1.5`; 256: `Lambda=[10.125 56.25 56.25]`, `Beta=[.0126 .0126 .0126]` | Weight spatial smoothness, patch fit and coefficient sparsity on the scaled maps. The coefficient penalty uses `Lambda.*Beta`; all three-component vectors follow `[T1 T2 Density]`. |
| DL `MaxIterations`, `InnerStopRule` | 128: 100 outer updates; 256: 80; `'one-step'` or `'tolerance'` | Set the outer budget and amount of dictionary learning between map updates. Each preset shares the prior weights across both DL methods. |
| DL `MapTolerance`, `DictionaryTolerance` | `1e-6`, `1e-4` | Both the absolute map change and the combined dictionary/coefficient change must meet their tolerances to stop. |
| LM `Tolerance`, `StepTolerance` | `1e-6`, `0` | Test the projected-gradient measure; optional relative-step stopping is disabled in both presets. |
| `h`, `GaussNewton`, DL `StepNorm` and QP tolerances | `1`; `'approximate'` for LM and DL; `'H01'`; optimality/function/PCG: `[1e-7 0 1e-6]` | Set grid spacing, curvature approximation, DL step norm and map-subproblem accuracy. |
| `nested_options.InnerMaxIterations`, `InnerToleranceScale`, `InnerDecay` | `1000`, `0.005`, `0.75` | Cap inner dictionary updates and set their decreasing change tolerance. A smaller scale requests a tighter inner solve, potentially increasing cost or reaching the cap. |

The LM choice `InitialDamping=r^2` follows the numerical choice in [Dong et al., Section 4.4](https://arxiv.org/pdf/1903.11979), where their undersampling factor `s` corresponds to this code's `r`. The decay `0.15` and 15-update budget are settings for this implementation, not values prescribed by that paper. LM has no spatial or dictionary penalty in this comparison.

`NoiseLevel=[]` disables discrepancy stopping for BLIP and LM. To try it in the four-method demo, uncomment the `lm_options.NoiseLevel=expected_noise_norm` and/or `blip_options.NoiseLevel=expected_noise_norm` lines after data generation. `NoiseLevel` is a noise **norm**, not `noise_std`; `DiscrepancyFactor` sets the residual threshold multiplier. Iteration limits are caps, and the saved `stop_reason` records the actual termination. LM's `Tolerance` tests its projected-gradient measure, while DL's `MapTolerance` and `DictionaryTolerance` test outer changes; `QPOptimalityTolerance` concerns a map subproblem. Meeting a step tolerance alone does not quantify closeness to stationarity without the constants in the corresponding bounds.

The DL outer change test follows the two-block structure of [Algorithms 2 and 4 in the paper](https://arxiv.org/pdf/2506.11977): both the absolute change between successive scaled maps in the selected `StepNorm` and the combined Frobenius change of `(D,C)` must meet their tolerances. The saved presets use `H01`; `H1` also includes the map-value term. DL does not compute a projected-gradient measure. LM retains its projected-gradient stopping rule and history.

Nested DL checks the **last inner D/C update** against `eta_k = 0.005 * sqrt(norm(D0(:))^2 + norm(C0(:))^2) / (k+1)^0.75`, where `k=0` is the first outer update and the scale uses the fixed initial dictionaries and coefficients. This differs from the **total D/C change across the whole outer update**, used by `DictionaryTolerance`. If an active map reaches the inner cap without meeting `eta_k`, the solver stops with `inner_tolerance_not_met` and returns the preceding complete iterate. One-step DL always performs one D/C update pair per active map; the nested tolerance and inner cap do not control it.

`GaussNewton='approximate'` uses local Bloch Gram curvature; `'exact'` uses sampled Fourier Gauss-Newton products. Both omit residual-weighted second derivatives. In DL, `QPRequireOptimality=true` and `QPMaxIterations=600` require a sufficiently accurate map subproblem before acceptance; `qp_firstorderopt` measures that QP's accuracy, not outer convergence. LM solves damped normal equations and clips the result to the bounds, using its damping schedule without a descent backtracking test.

## Mathematical description

For context, the underlying approach is summarized by the paper's discrete problem $(P_2)$. Written with consistent component indices and explicit constraints, it is

```math
\begin{aligned}
\min_{u,D,C}\quad
& \frac{h^2}{2}\bigl\lVert F_d(u)-f^\delta \bigr\rVert_2^2
+ \frac{\alpha}{2}\bigl\lVert \nabla u \bigr\rVert_{U_1}^2
\\[0.6em]
& {}+ \sum_{j=1}^{3}\lambda_j\left(
\frac{1}{2}\bigl\lVert P[u_j/M_j]-D_jC_j \bigr\rVert_F^2
+ \beta_j\bigl\lVert C_j \bigr\rVert_1\right)
\\[0.8em]
\text{subject to}\quad
& u\in U_{\mathrm{ad}},\qquad D_j^{\mathsf T}D_j=I,\qquad j=1,2,3.
\end{aligned}
```

Here $F_d$ combines Bloch dynamics and sampled Fourier measurements, $f^\delta$ denotes noisy data, $P$ extracts image patches, and $M_j$ scales each parameter map. Orthogonal dictionaries $D_j$ and sparse coefficients $C_j$ describe local image structure; $U_{\mathrm{ad}}$ imposes parameter bounds. The gradient term provides spatial regularization.

**Implementation convention:** MATLAB arrays use the channel order `[T1, T2, Density]`. Both patch and spatial penalties act on shifted, scaled maps $x_j=(u_j-u_{\mathrm{ref},j})/s_j$, controlled by `ReferenceTimes` and `Scales`. The algorithm alternates dictionary/coefficient updates with bounded LM/Gauss-Newton map updates. The current demo settings are starting configurations, rather than an exact reproduction of the paper's experiments.

DL uses all valid, overlapping patches with stride one and zero exterior values for the scaled maps in its spatial difference operators. These exterior conditions do not fix pixels outside the body mask. By default, each initial dictionary is obtained from an SVD of the starting patch Gram matrix, and its coefficients are initialized by soft thresholding. The common `u0`, patch size and sparsity settings therefore give both DL methods the same initial dictionaries and coefficients.

## Input data and outputs

The qMRI reconstruction demos use `data/sequence_parameter_middle.mat` for the RF pulse sequence. The four-method comparison currently generates artificial 256 x 256 reference maps and subsamples them according to the selected preset; its input section also offers `data/PWbrain256.mat`, which is the standalone demos' default. Measurements are simulated from the selected maps. The image-denoising demo loads only the selected image variable and adds noise directly to the image; it does not use the RF sequence.

### Choosing the RF sequence length and TR

Set `L` in the selected parameter preset (or the standalone demo's manual settings). Every qMRI demo calls [`select_rf_pulses`](helper_functions/select_rf_pulses.m) to select `L` pulses across the **entire** stored RF sequence, using `round(linspace(1,numel(sequence.RF),L))`. For example, `L=30` selects 30 entries spread from index 1 to index 1000. Selection preserves the stored pulse values and complex phases without interpolation or filtering. Both endpoints are included for `L>=2`; `L=1` selects the first pulse. **Lengths from 1 to 1000 are supported**; the demo defaults remain `L=100`.

```matlab
addpath('helper_functions');
sequence = load(fullfile('data','sequence_parameter_middle.mat'),'RF');
L = 1000;
[RF,indices] = select_rf_pulses(sequence.RF,L);
TR_ms = 12;
TR = TR_ms*ones(1,L);
plot(indices,abs(RF)*180/pi,'o-');
xlabel('Stored pulse index'); ylabel('Flip angle (degrees)');
```

The source RF magnitudes represent flip angles in radians, ranging from 0 to about 64.34 degrees. The 1000-frame file continues the original **120-frame motif** exactly: 50 active pulses, 10 zero-RF recovery frames, 50 active pulses at half amplitude, and 10 more recovery frames. The original zero RF phase is retained. Alternating high/low flip-angle blocks and recovery intervals are consistent with the general design in [Ma et al. (2013), Methods: Sequence Design](https://pmc.ncbi.nlm.nih.gov/articles/PMC3602925/); this continuation uses the project's existing values and is not a reproduction of that paper's protocol or an optimized acquisition.

The first 205 RF and TR entries are unchanged. A byte-for-byte backup of the original file is kept as [`data/sequence_parameter_middle_205.mat`](data/sequence_parameter_middle_205.mat). **Shorter runs now select different pulses**, because selection spans all 1000 entries. To reproduce an old acquisition, load RF from the backup before calling `select_rf_pulses`.

`TR_ms` is independent of RF selection: the demos generate `L` identical repetition times, shared by data simulation and reconstruction. Both presets use 12 ms; the standalone BLIP demo's manual default is 10 ms. The MAT file also contains 1000 variable TR values (about 11.17 to 30.74 ms), formed by independently repeating the original 205-entry TR vector, but these are **not used by the demos**. To use them in a custom simulation, select `TR=sequence.TR(indices)` using the same indices as RF. Downsampling RF does not accumulate the omitted repetition times: at 12 ms, `L=100` gives a nominal pulse-train duration of 1.2 s and `L=1000` gives 12 s. All methods in the four-method comparison use the same selected acquisition.

The extension is reproducible with [`extend_rf_sequence`](helper_functions/extend_rf_sequence.m). The MAT file retains `RF`, `TR`, `L`, and `df`, and adds `RFDesign` metadata:

```matlab
addpath('helper_functions');
original = load(fullfile('data','sequence_parameter_middle_205.mat'));
extended = extend_rf_sequence(original,1000);
% Save under a new name to inspect or customize it.
save(fullfile('data','sequence_parameter_custom.mat'),'-struct','extended','-v7');
```

MATLAB R2021b validation covers all selectable lengths, finite Bloch signals and derivatives, finite-difference derivative agreement at 1000 frames, and local identification of `[T1,T2,density]` on 51 tissue pairs spanning T1=100--5500 ms and T2=10--600 ms with T2<=T1. At fixed TR=12 ms and unit density, the median predicted standard-deviation ratios for 1000 versus the original 205 frames were approximately `[0.506,0.779,0.927]`, using the full three-parameter sensitivity matrix and equal independent signal noise. These are local simulation diagnostics, not reconstruction-error guarantees; spatial undersampling and regularization are not included.

Earlier versions selected the prefix `1:2:2*L`. Full-sequence selection changes the acquisition even at `L=100`, so earlier numerical benchmarks should not be expected to reproduce exactly. New comparison files save the actual `RF`, `TR`, `zeta`, and `experiment.RFIndices`; older result files still support replotting but may lack these acquisition arrays.

For context, [Ma et al.'s original MRF experiment](https://mriquestions.com/uploads/3/4/5/7/34572113/mr_fingerprinting_nature11971.pdf) used variable TR between 10.5 and 14 ms for one sequence. [Zhao et al.'s sequence-design study](https://arxiv.org/pdf/1710.08062), Section III-A.2, used ordinary excitation angles between 10 and 60 degrees and TR between 11 and 15 ms, with a separate allowance for an initial inversion pulse. This makes our approximately 0-64-degree angles and 12-ms TR plausible starting magnitudes for numerical experiments; it does not establish that our particular sequence is optimal. Constant TR is also an explicit simplifying choice in [Dong, Hintermueller and Papafitsoros](https://arxiv.org/pdf/1903.11979), Section 2.3.

Uniform RF selection is a resampling rule, not sequence optimization. Changing `L` changes the excitation dynamics, duration and available information, so a short run such as `L=30` should not be assumed to retain the accuracy of `L=100`. Zhao et al. optimize acquisitions for different lengths separately. Check reconstruction errors for the intended `L`, noise and undersampling. Also review `r`: with `zeta=mod(0:L-1,r)+1`, `L<r` does not complete even one cycle through all sampled-row offsets. These numerical choices are not a validated scanner protocol.

### Using your own reference maps

To use your own reference maps in a qMRI demo, select a MAT file containing equally sized, real, finite, two-dimensional arrays named `T1`, `T2`, and `Density` as described in the quick start. Relaxation times are in milliseconds; density must be nonnegative, with zero marking the background. The four-method, standalone LM and dictionary-regularized demos replace background T1/T2 values with `reference_times` before simulation. Foreground values must satisfy the selected bounds, and each patch must fit the reduced image. Review the physical bounds, scaling, and sampling settings for the new input. For image denoising, supply just one real, finite, two-dimensional numeric array and set `image_variable` to its name; adjust `image_scale` and `noise_std` to its units.

The demos leave reconstructed maps and available iteration histories in the MATLAB workspace. Only the four-method comparison automatically saves `results.mat`, including errors, residuals, timings, stopping reasons and experiment settings. Save workspace variables explicitly if numerical results from the other demos are needed later.

### Reading a saved comparison

```matlab
run_folder = fullfile(pwd,'data','comparison_all_<timestamp>');
s = load(fullfile(run_folder,'results.mat'));
disp(s.comparison);
nested_history = s.saved_histories{4}; % BLIP, LM, one-step DL, nested DL.
nested_options = s.saved_options{4};
disp(nested_history.stop_reason);
```

| Saved variable | Contents |
| --- | --- |
| `truth`, `mask`, `u0`, `reconstructions`, `method_names` | Physical reference maps, body mask, common start and four reconstructed map arrays in the stated method order. |
| `comparison`, `rmse` | Final errors, residuals, timings and stopping reasons; `rmse` has methods in rows and `[T1 T2 Density]` in columns. |
| `saved_histories`, `saved_options` | Per-method histories and the options actually passed to each solver. State histories include iteration zero; completed-update histories start at update one. |

The MAT file is saved **before PDF export**, so numerical results remain available if plotting fails. It does not contain the noisy measurement array or final DL dictionaries/coefficients; retain and save those explicitly if needed. Use `export_comparison_reports` to rebuild all reports, or the individual plotting functions above to draw selected figures. The compact-PDF example exports only its eight files.

### Interpreting the results

The four-method comparison defines the body by `mask = truth(:,:,3)>0`. For each parameter, the reported percentage error is `100 * norm(estimate(mask)-truth(mask)) / norm(truth(mask))`; RMSE also uses body pixels and is expressed in the parameter's physical units. `BackgroundDensityRMS` uses density outside the body in the **unmasked reconstruction**. The known body mask is used for common initialization when enabled and for evaluation; it is not a constraint in the four subsequent solves. `design.ZeroBackground` affects display copies only.

`DataResidual` is the norm of the complex residual on acquired Fourier samples, expressed consistently for all four methods. Compare this residual and the map errors across methods. DL's full objective includes spatial, patch-fit and sparsity penalties; BLIP and LM use data fit only. Full DL objectives are directly comparable between the two DL methods only when their regularization settings agree.

Read `StopReason` together with the histories:

- `small_joint_step`: DL met both outer change tolerances.
- `projected_gradient`: LM met its projected-gradient tolerance; `info.converged` is true only for this LM stopping reason.
- `discrepancy`: BLIP or LM reached an explicitly enabled noise-level threshold.
- `small_signal_step`: BLIP produced zero signal change or met an enabled relative signal-change tolerance.
- `max_iterations` or `max_trials`: the configured update or trial budget was exhausted.
- `inner_tolerance_not_met`, `backtracking_failed`, or `linear_solve_failed`: an inner calculation or acceptance requirement failed. DL records `last_inner_*` and `last_qp_*` diagnostics; LM records `last_linear_*`; BLIP records trial counts and accepted-step backtracking histories.

These are the most common reasons; optional small-step tests and LM's projection/nonfinite checks have their own reasons. A budget or failed inner calculation is not a convergence certificate. The DL inner-tolerance plot shows the last inner D/C change, whereas its successive-iterate plots show changes between complete outer iterates.

### Plot reports

The other demos use the same plot style: shared map/error color limits, linked zoom insets, compact PDF rows, and profile reports. They export to a new time-stamped folder under `data/demo_reports/`. Edit each demo's `design` settings to choose the zoom, profile row, background display, or figure visibility; the common defaults are in [`plot_routines/reconstruction_plot_design.m`](plot_routines/reconstruction_plot_design.m). Convergence PDFs show successive-iterate changes in place of projected-gradient stationarity plots. DL reports show separate absolute map and combined `(D,C)` changes, with dotted stopping-tolerance lines. LM shows the physical L2 change as a diagnostic while retaining projected-gradient stopping. Change histories begin at the first completed update. The denoising demo exports a single image channel, while legacy BLIP omits initialization and convergence reports because its interface does not return those quantities.

PDF export normally uses vector graphics. If MATLAB's vector renderer fails, `export_reconstruction_pdf.m` retries on a fresh hidden figure, then falls back to an image page at `design.Resolution` DPI with a warning if necessary; existing PDF pages are preserved when an export fails.
